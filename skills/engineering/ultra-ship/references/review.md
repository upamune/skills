# 差分に応じたレビュー

まず要求・規約・不具合を対象差分に照らして確認する。レビュー済みの箇所を再確認するのは、その後の変更で影響がある場合に限る。

## 追加の観点

| 具体的な必要 | 利用可能なら使うスキル |
| --- | --- |
| 深い構造監査の依頼、または実際に見つかった構造問題 | thermo-nuclear-code-quality-review |
| 差分の重複・複雑さ・読みにくさを解消する | simplify |
| 差分の不要な防御、冗長コメントなどを整理する | deslop |
| 要求と repo 規約に沿うレビューを独立して行う | code-review |

不要な `review:thermo` / `review:simplify` / `review:deslop` は `skipped --note` で理由を残す。追加スキルがなくても、必要なレビューは現在のエージェントが行える。構造を変える必要がある場合は、その後に整理と影響箇所の確認を行う。

## 独立レビューを使う場合

利用可能な、委譲が許可されたレビュアーに diff の範囲、要求の原文、関連する repo 規約、読み取り専用であることを渡す。結論や想定される指摘で誘導しない。スキルが必要なら本文と必要な reference を渡す。パスだけでは外部 CLI が repo 外のスキルを読めない場合がある。

レビュアーには実際に問題となる箇所、影響、修正案を求める。ホストが根拠を確認し、依頼範囲内の指摘を修正する。必ず別のモデルに交代する必要はなく、書き込みを委譲する場合も同時に一人だけにする。

修正した箇所と影響する検査を確認して終了する。新たな証拠や変更がない状態で「指摘ゼロ」を得るための総点検を追加しない。同じ問題が 3 回の試行で収束しなければ blocked にする。

## 指摘の記録

`checkpoint.py round` に指摘の配列を渡す。指摘がないレビューは `[]`。

```json
[
  {"id": "F1", "where": "src/a.ts:42", "finding": "問題と影響", "fix": "修正案", "safe": true, "applied": true, "note": "どう修正し、何を確認したか"}
]
```

`safe` は「現在の依頼・仕様の範囲で適用できる」の意味。仕様通りに直すバグ修正も含む。要求外・誤検知・方針未確定のものは `safe: false` とし、見送った理由を `note` に記す。未処理を隠すために分類を変えない。必須の修正が未解決なら工程は blocked にする。

```bash
python3 "$S" round review:code-review --reviewer host --findings <file.json> --summary "確認範囲と結果" --commit <sha>
python3 "$S" phase review:code-review done
```

各記録はその時点の差分を示す。後の変更が指摘内容に影響したら記録と検証を更新する。
